# 玻璃外观与桌面图标开关验证

日期：2026-10-12。环境：Windows 11 `10.0.22631.0`、x64、.NET 10.0.12、窗口 DPI 144。

## 玻璃与清透范围

保留稳定的单层 Composition GaussianBlur 与原圆角裁切，用 WPF `GlassEdge` 添加向内衰减的切面高光与暗部。当前为光影模拟，没有背景图像变形，不实现物理折射。透明度仍为 0%–100%，实际效果范围扩大：除底色 alpha 外，背景模糊随值升高从约 32.35 降到 0.35，100% 可接近清透。

此前背景 Transform2D 与环形合成实验的首次运行因不支持的 StrokeBrush 类型失败；改用环形裁切后，验证在 SingleInstanceVerifier 超时，验证背景未及时退出。用户同期反馈黑屏，因此撤回整条实验路线。日志能确认异常和退出清理不足，不能证明显卡或 DWM 故障，也不能把超时归因于某个 GPU 效果。当前仅使用原有单层模糊，退出先隐藏验证背景和窗口。

## 验证

Release x64 构建 0 个错误、0 个警告。执行 `scripts/run.ps1 -Verify -NoBuild -DesktopIconTest`，退出码为 0，142 项检查通过：

- 透明度 0% 底色 alpha 为 255，100% 为 0；100% 主面板与 Dock 的实际 blur 均小于 1，80% 小于 10。前景 opacity 保持 1。
- 截图复核清透、磨砂状态与设置控件；原 32/40 DIP 圆角检查通过，圆角外背景像素最大 RGB 差为 0。
- 实际隐藏/恢复 Windows 桌面图标，澄桌窗口和入口保持可见及顺序；重复请求不反转状态，设置重开读取真实状态。
- 桌面开关测试结束恢复测试前状态，不删除或移动桌面文件。系统保存显示状态，退出澄桌不自动恢复。
- 托盘、单实例唤回、最小化保留 Dock、透明度持久化、图标池与 Dock 排序等原检查通过。

另以普通启动方式使用现有用户配置（透明度 100%），实际窗口读取和截图检查主面板、Dock 与设置可见，重复启动恢复同一进程。该检查没有创建测试背景或修改桌面开关。最终只保留普通应用进程，验证进程已退出。

两种本地 EXE 已重新生成：轻量版 9,869,824 字节，离线版 72,863,232 字节。最终轻量 EXE 从 `C:\Windows` 启动，复用私有运行时，执行普通验证退出码为 0，133 项检查通过；该轮只读取桌面状态，不执行桌面开关集成修改。
