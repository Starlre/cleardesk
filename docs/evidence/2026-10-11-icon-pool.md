# 空面板与图标池验证

日期：2026-10-11。环境：Windows 11 `10.0.22631.0`、.NET SDK 10.0.401、运行时 10.0.12、x64、窗口 DPI 144。

## 使用行为

主面板首次启动不显示应用图标，Dock 仅保留打开面板的按钮。后台扫描的桌面和开始菜单快捷方式进入独立图标池。点击「添加」，搜索并勾选应用，再点击「添加到面板」；取消或关闭不会添加图标。图标池标记已添加项，避免重复加入。文件导入和 Explorer 路径拖入先进入图标池，确认后才加入面板。

面板与排序写入 `panel-state.json`，重启仅恢复已选择入口。旧版 `state.json` 保留但不自动迁移，因为它不能区分自动填充与用户选择。右键移除仅移除面板入口，不删除快捷方式；图标仍可从池中重新添加。尚未确认添加的外部文件候选仅保留在当前会话。

## 检查结果

执行 `scripts/build.ps1` 和 `scripts/run.ps1 -Verify -NoBuild`。最终 Release x64 构建 0 个错误、0 个警告，75 项检查全部通过。

- 本机图标池 469 个唯一候选，合并 88 个重复快捷方式；启动面板 0 个入口。
- 多选与搜索不直接添加；筛选后保留未显示项的选择。通过复选框可访问性接口确认选择绑定，再通过真实添加按钮事件确认加入。
- 取消不改变面板；已加入项目禁用重复选择，移除后可重新加入。
- 保存重启后只恢复用户选择，新扫描项不会自动进入面板；扫描目录之外的手动文件可恢复。
- 移除全部入口后重启保持为空，损坏状态文件不会自动填充全部候选。
- 最小化、隐藏和恢复主面板时，图标池及其玻璃层同步显隐，保留未确认选择。
- 验证图标池的玻璃窗口直接位于图标池 UI 后方，截图确认主面板不再夹在中间。
- 既有搜索、分页、排序、去重、Dock、玻璃裁切和最小化检查通过。未运行真实鼠标注入测试。

验证使用独立状态和测试文件，不改动用户选择文件，不启动外部应用。
