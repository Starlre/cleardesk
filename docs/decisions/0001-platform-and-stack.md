# ADR-0001：首发平台与主技术路线

- 日期：2026-10-11
- 状态：继续 WPF 路线，完整窗口验收尚待完成
- 决策依据：用户参考图、桌面启动器/Dock 的产品范围与 Windows 集成需求

## 决策

首发优先 Windows 11，采用 C#、.NET 10 LTS、WPF/MVVM、Win32/Shell COM 与 SQLite。玻璃材质首先验证 Windows 11 22H2 及以上的文档化 DWM 路线。

界面框架的最终确认依赖 V1：背景材质、大圆角、阴影、命中区域和焦点行为须同时达到核心要求。Core 与 Windows 适配服务保持独立，以控制潜在框架切换成本。

## 备选方案

| 方案 | 适合点 | 代价与边界 |
| --- | --- | --- |
| WPF | Windows 互操作成熟，MVVM 与自定义界面可控 | 玻璃、窗口形状和合成组合需要专门验证 |
| WinUI 3 | Desktop Acrylic 接入更直接，合成能力较强 | 任意轮廓、命中、焦点和 Shell 集成仍需验证 |
| Tauri 2 + React + Rust | 网格、前端布局与动画开发方便 | WebView 内的 CSS 模糊不等于桌面模糊，仍需 Windows 适配 |
| Electron | Web 生态成熟，原型构建方便 | 常驻开销与分发体积通常更高，须以实际测量判断 |

## 调整条件

- WPF 无法在合理实现成本内同时满足材质、轮廓和命中要求：验证 WinUI 3，再记录是否切换。
- 用户明确要求跨平台或优先复用 Web 技术：重新评估 Tauri，不把 Windows Dock 行为直接视为跨平台能力。
- 用户明确要求 Windows 10：单列兼容矩阵并决定允许的材质降级；当前不声称已支持。

不把未文档化的窗口合成接口或 Explorer WorkerW 挂载作为首版基础依赖。

## 当前限制

项目内已准备 SDK 10.0.401，WPF 实验能够构建运行。非 layered HWND 与文档化 DWM 接口成功，深浅主题截图已有背景模糊的视觉证据。

后续像素检查发现系统 Acrylic 会绘制矩形背景，当前已禁用该背景，改用独立 Windows Composition 合成窗口、24 px GaussianBlur 和圆角几何裁切。WPF 非 layered 前景与背景同步位置、显隐及层级，图标文字保持清晰。Dock 真实鼠标移动、缩放和焦点检查通过；阴影、外部透明区命中、系统透明开关、多屏与混合 DPI 尚待完整验收。证据支持继续 WPF 路线，正式 SQLite 与模块拆分尚未实现。
